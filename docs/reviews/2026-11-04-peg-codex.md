# Independent review: PEG group semantics

Reviewed 2026-11-04: `cd7c33c`'s architecture §20.1–20.14 and draft
Program 2.0, with the working-tree §19 dependency, Program 1.1,
SPEC, the requested DEVLOG decisions/status, the conformance audit and its
quotation correction, and the local authoritative RFC 8610/9682 texts.
This is a design review, not a review of an implemented PEG VM.

**Do not freeze Program 2.0 yet.** The array semantics and the relaxed-query
idea are defensible. The proposed executable contract still has blockers in
recursive stack storage, scratch sizing, unordered-map lookup and cross-driver
charging. Map witness equivalence and several normalizations also need changes.

All probes are synthetic and live in `.cache/pegrev-codex/`. Only this report
is an intended tracked change. No network, git mutation, emission, project
gate, snug Rust/wasm build or performance benchmark was run. Existing unrelated
working-tree changes were present before review and were preserved.

## Evidence actually obtained

`node .cache/pegrev-codex/probes.mjs` ran 16 schemas through the designer's
prototype and the supplied Ruby wrapper. Final results are in `results.json`,
with individual schemas, CBOR and Ruby logs. Prototype option `member` is the
document's **reference** mode; `branch` is its alternative rule A, not the
reference mode. Ruby rc65 is a parse error, not a data refusal. An initial run
used a three-second subprocess timeout; only the completed ten-second rerun is
used below. The prototype supplies Boolean semantic evidence, not evidence for
the proposed tiers, memoization, charging, witnesses or scratch layout.
An additional prototype check of finding 10's four-level nested finite
repetition on 32 zeroes accepted in both modes (`nested-finite.json`).

`node .cache/pegrev-codex/bounds.mjs` independently built relaxed first/follow
sets, computed FL/B and interpreted finite PEG trees. Its 1,200 generated
trees, all binary inputs of lengths 0–6, produced **152,400 cases**, **125,683
ENTRY tests**, and **zero query-superset or read-back-bound violations**.
151,384 cases had finite B; maximum observed read-back was five records. This
is bounded testing of finite trees, including nullable and failing bodies and
nested finite/unbounded repetitions. It is not exhaustive over grammars and
does not execute CALL, the actual compiler, or the incremental VM.

## Numbered findings

### 1. Blocker — recursive activations have no complete storage contract

**Sections:** architecture §20.5–20.6; Program 2 §3, §5.2, §9.2–9.4.

```cddl
r = [g]
g = (0, ? g, 1)
```

Data `[0,0,1,1]` must succeed under the proposed run; the prototype does.
While the inner `g` runs, the outer SEQ continuation and optional REP state
must survive. `depth` excludes CALL nesting; the block gets only
`4 * depth` static stack words, while only **CALL frames** are assigned to
the downward arena. Saving a CALL return address alone cannot preserve the
caller SEQ/REP frames if the callee reuses that static stack. Letting `sp`
continue growing instead exceeds the declared static allocation.

**Fix:** specify an activation convention: either move every frame in a
recursive activation into the arena, or save/restore the complete static
stack segment at CALL. Define its allocation, suspension, unwind and charges.
Include these words in the arena bound. A group cycle can consume one element
while retaining O(depth(G)) frames, giving O(n * depth(G)) stack words, in
addition to records. The displayed `n * (W + memo columns)` bound is only a
record bound, not a bound on an A2 array's total arena consumption.

### 2. Blocker — the eight-word machine state contains at least nine fields

**Sections:** Program 2 §5.2, §8 rule 5′, §9.2; architecture §20.6.

The declared fields are `pc, idx, sp, status, want` (five), plus farthest
event index, kind, position and empty-record flag (four). That is **nine**
words before the element-head offset that rule 5′ also says is retained.
`machine[8]` and ARRAREA allocate eight. A schema such as
`r=[(uint,tstr)//(uint,bstr)]` on `[1,false]` exercises the failure tracker;
every array block already suffers the allocation discrepancy.

**Fix:** provide an actual offset table, including any explicitly packed
fields, retained offset and recursive activation pointers, and derive all
frame/scratch formulas from it. Do the same for map commitment and failure
tracking. A normative format cannot rely on implicit packing to make its
allocation safe.

### 3. Blocker — inherited key lookup still assumes ascending wire keys

**Sections:** Program 2 §6.1 step 1 and §10; Program 1.1 §8.3 steps 2–3;
architecture §19.2–19.5.

```cddl
r = {a: int, b: int}
```

Data `{b:2,a:1}`, bytes `a2616202616101`, is valid under §19. The canonical
copy deliberately retains wire order. The inherited KEYS binary search uses
`lo` one past the preceding key id/insertion point, and its per-map naming
cursor only advances. After finding `b`, it cannot find `a`. Program 2 calls
this lookup “format 1 §8.3 step 2” and still charges cursor steps; it does
not explicitly replace the ascending-only rule. PF_CANON suppressing an order
refusal does not repair the search.

**Fix:** specify full-range lookup of every key on unordered input, plus
independent lookup in the map's named-key index. Keep monotone cursors only
behind a proved ascending-order condition. Define the charge schedule for
both routes. Include this case under valid-CBOR buffer, canonical and framed
session execution before treating §19 as a completed dependency.

### 4. Blocker — canonical precharging and native session charging disagree

**Sections:** architecture §19.3–19.5, §19.7, §20.6–20.7; Program 2 §10.

```cddl
r = [uint, {0*1000 int => int}]
```

Use `[0,{99:0,98:0,...,0:0}]`, with descending keys in the inner map.
The buffer canonical path discards the deterministic attempt and charges
the deferred duplicate-sort units **before the VM starts**, reporting budget
at the root if that precharge exceeds the allowance (§19.5). A native framed
session evaluates the prefix and pairs before its deferred check at map end
(§19.7). Choose an allowance below the sort charge but above the short root
and first-element prefix: the buffer refuses at the root; the session can
execute schema work and exhaust within the map instead. Varying the number
of keys makes the sort charge arbitrarily larger than the fixed prefix.

This counterexample predates the PEG delta, but §20 explicitly depends on
§19 and promises equal offsets, budget usage and exhaustion points. Adding
record/PEG charges “after each child” does not reconcile these orders.

**Fix:** define one logical event order for canonical work, duplicate checks,
record allocation, PEG work and resource failures on every driver. Prefer
charging deferred checks at their logical container end on both routes,
despite doing physical preprocessing earlier. Specify budget offsets there.
Test budgets immediately before/at/after each event under whole-item and
framed routes, indefinite encodings, EMBED and every split.

### 5. Major — F and the generic map machine do not produce the same cut witness

**Sections:** architecture §20.5 F/T, §20.8; Program 2 §6.2, §6.4, §8.

```cddl
r = {* tstr ^=> int, ? "a" => any, ? "b" => any}
```

Data in wire order `{b:"x",a:"y"}`, bytes `a26162617861616179`.
Both cut modes reject; both pairs are acceptable to some member, so M1 does
not mask the issue. The F pass retains its cut event at wire pair zero,
`b`. The generic run picks `a` first in EC order and returns immediately
on that cut failure. Its actual failure trace contains `a`, yielding a
different schema-named key from F's `b`.

The statement “smallest wire index” does not specify whether it ranges over
encountered events or all hypothetical violations, including pairs after the
member has stopped. T as specified only encounters the first violation.
Unbounded cut members are order-sensitive for diagnostics even though their
Boolean result is order-independent. Thus T's claim that only finite-max
members ever need pick order is too strong for the witness contract.

**Fix:** choose an explicit witness predicate. Either retain enough EC order
in F/S to reproduce the operational first cut, or define a separate diagnostic
scan over verdicts and make every tier perform it, with charges and exact
scope relative to maximum/consumed pairs. Gate forced-F/S/T witnesses, not
just verdicts, using named keys and permuted encodings.

### 6. Major — “single cut-free member” does not justify collapsing nested occurrences

**Sections:** architecture §20.5 F; Program 2 §3 lowering and §6.3.

```cddl
r = {2*2 (+ int => int)}
```

Data `{1:1,2:2}` rejects: the first inner `+` greedily takes both pairs; the
second inner `+` fails, so the outer minimum two is unmet. Multiplying bounds
to obtain `{2* int => int}` accepts. Both prototype and Ruby confirmed this
difference. There is exactly one cut-free member in the parenthesized group.

**Fix:** restrict the stated normalization to a REP whose child is a plain
MEMBER with occurrence exactly 1..1, or prove each additional rewrite
separately. Do not generally multiply member and group occurrence bounds.
Keep this nested case T. Make the architecture and the syntactic tier test
agree on what normalization precedes classification.

### 7. Major — the inherited large-minimum rewrite contradicts R4

**Sections:** architecture §20.2/D035 inheritance; Program 2 §3 invariants.

```cddl
r = [16777216*16777216 (? int)]
```

Data `[]`. R4 immediately satisfies the repetition after its first
zero-length success. However, §20.2 makes minima at least 2^24 unsatisfiable,
and Program 2 requires such a node to be FAIL. No input entry limit rules
out these **empty** iterations. The result is a semantic contradiction,
not merely refusal of a very large input. The prototype's parser has its
own one-million bound, so this counterexample is established from the two
written rules, not a claimed prototype run.

**Fix:** preserve the possibility of zero-length success before applying
count saturation. For large minima, use a proved representation/limit refusal
or a nullable-body-aware semantics; do not silently lower valid empty matches
to FAIL. Also explicitly lower max=0 to EMPTY, since the REP record requires
max≥1. Use checked/saturating arithmetic in maxlen, FL, B and all products.

### 8. Major — A2 memo storage has no end-of-input row

**Sections:** architecture §20.5–20.6; Program 2 §3, §5, §9.4.

```cddl
r = [* ((* uint, tstr) // uint)]
```

Data `[1,2]`. The inner unbounded REP is multi-start and therefore has a
link pair. The final outer iteration enters it at index `n=2`, where it
successfully consumes zero before `tstr` fails. Its memo probe/store addresses
index n, but only n element records were allocated. On `[]`, this same A2
shape can need a memo row before any element record has been stored.

**Fix:** allocate a sentinel row for n, or specify and charge a separate
EOF memo bank. Define link encoding for a zero-length success at index zero:
`end=0, iterations=0` cannot also mean “unknown”. Include sentinel cells,
initialization and overflow in scratch/arena bounds.

### 9. Major — RFC cut prose, pseudocode and frame-bit implementation differ on lifetime

**Sections:** architecture §20.2 cut modes/R9, §20.14 Q2; Program 2 §6.4.

```cddl
r = {* (a: int)}
```

Data `{a:1}`. The prototype accepts in rfc mode: it snapshots commitment
before **each attempted iteration**, so a later failed attempt with no key
match can stop the repetition. The prose instead says “from then on” every
enclosing repetition is disabled; Program 2 sets a frame bit when a cut key
matches and has REP read it on failure. A sticky bit on that REP would refuse
when the second iteration fails to find `a`.

The authoritative §3.5.4 requires lock-in “independently of whether the value
matches as well” and says on value failure “the entire map fails to match”.
Appendix A says cuts disable “alternatives in choices containing this choice”.
Those are strong support for global failure on a bad cut value; they are not
a complete operational specification of commitment across successful
iterations. The draft must not call its extra lifetime rules settled RFC text.

**Fix:** define dynamic choice/iteration scopes and commitment epochs,
including clearing/reset and propagation on successful return, ordinary
failure and `fail!`. If adopting the prototype, state that the stop alternative
of a fresh iteration is eligible when that attempt saw no cut, while a later
failure of an enclosing alternative still observes cuts within it. Add this
success-then-stop example alongside M09/M20; do not implement a sticky global
Boolean. Type-level alternatives remain outside the map's commitment scope.

### 10. Major — a general linear-time claim is false, and the narrower array claim is unfinished

**Sections:** D270's cost claim; architecture §20.5 memoization; Program 2 §3,
§5.2, §6.4, §10.

```cddl
r = {* (int => int // tstr => tstr)}
```

On n text/text pairs the T machine's first alternative examines all n
remaining pairs and fails; the second takes one. Subsequent iterations
examine n−1, n−2, … pairs in the first member. There are at least
`n(n+1)/2` key-verdict examinations for a fixed-size G. All pairs match the
schema. Array memoization cannot help this set-state map execution.
Scanning consumed records to locate unconsumed ones introduces further
work; those skips must also be charged unless an explicit data structure
eliminates them.

The array claim also misses **composed finite bounds in A1**, which has no
memo columns:

```cddl
r = [* ((2*2 (2*2 (2*2 (2*2 uint))), tstr) // uint)]
```

On 32 zeroes the first alternative repeatedly consumes 16 uints before its
tstr fails; the fallback consumes one uint. Generalize to k nested `2*2`
operators and n≥2^(k+1) uints. B=2^k, W=1 and the tier is A1. Work is
Omega(n*2^k) for O(k) grammar nodes, although **every finite maximum is two**.
The stated additive O(n*m) exception for finite-max-m nodes does not account
for multiplying nested bounds. k=10 already fits the default ring cap
(1,025 words), so this is not merely an unrepresentable asymptotic family.

Even a single `r=[* ((0*1000000 uint,tstr)//uint)]` repeatedly scans finite
bounded suffixes; that simpler case is covered by the admitted O(n*m)
exception, and already prevents an unqualified linear-time guarantee when
numeric bounds take constant Program words. The proposed link algorithm
has no executable transition specification proving endpoint/count correctness,
EOF behavior, or cost of incremental path compression. “Every step is charged”
is a work bound by budget, not a proof of packrat linearity.

**Fix:** state separate complexity contracts: precomputation, non-recursive
arrays under explicit memo assumptions, finite-count exception, recursive
arrays, and maps. Accept budget-bounded quadratic maps if that is the product
decision. For arrays, either specify and independently test the memo/link
machine, or ship no memo columns and promise only budget-bounded work.
Do not advertise D270's general nodes-times-elements bound.

### 11. Major — arena bounds and resource offsets omit necessary state

**Sections:** architecture §20.6; Program 2 §8, §9.2–9.4.

```cddl
r = {int => int, int => 6}
```

For `{3:5,4:6}`, lower the arena so both T records fit but a subsequent trail
push does not. That push happens at map end, after pair bytes have passed.
The required `group_limit` offset is the head of the pair whose trail entry
did not fit. A record stores key id, flags, verdicts and optionally rank;
it stores **no original pair offset**. Pair index cannot reconstruct an
offset when keys and values have varying byte lengths. A CALL frame allocated
during an A2 rewind has an analogous problem for an old element index.

The advertised total also omits the recursive frames in finding 1, EOF memo
storage, and aggregation across simultaneous blocks/open containers. The
single active T trail has at most n entries because each consumed pair is
on it once; failed branches pop it. That useful bound does hold. It does
not bound the records and recursive frames of the whole validation.

**Fix:** either add original offsets to records and charge them, or define
end-run resource offsets at the containing item's retained head. Specify
the sum over all retained blocks/ancestors, actual frame costs and sentinel
rows, checked allocation arithmetic, and the exact precedence of allocation
versus charging. Keep allocation and overflow checks inside kin.

### 12. Major — map failure tracing and S's deferred state need an operational definition

**Sections:** architecture §20.5 S, §20.8; Program 2 §5.2, §6.2–6.4, §8–9.

```cddl
r = {("a" => int, "b" => int) //
     ("c" => int, "d" => int, "e" => int)}
```

Data `{a:1,c:1,d:1}`. The intended “most pairs consumed” trace should select
the second branch and missing `e`, rather than missing `b`. After both
failed SEQs undo, their returned trail lengths are identical. The machine
must retain the failure's consumption score and selected trace before undo.
The draft does not define whether the score is prefix consumption, a
high-water mark through nested failed iterations, or another quantity, nor
give fields/transitions that preserve it.

For S, `r={+ tstr => int, ? (a: int)}` on `{z:1}` is a simpler boundary.
Its root member's minimum is satisfied by an unnamed pair handled before
the end-run. A map machine scanning only slots sees no pairs and fails unless
it incorporates the saved unnamed count. Saved unnamed cut events must also
be merged at the member's source position, after preceding literal subtrees
have run. This is implied by intent but absent from §6.4's MEMBER algorithm.

**Fix:** define failure metadata and its update/undo rules, and explicitly
define S MEMBER evaluation from saved unnamed counts/events plus currently
unconsumed slots. Charge any trace replay. Preserve the shallow end witness
as an intentional D024 revision; do not claim it is the old deep witness.

### 13. Minor — the verifier's O(nodes) statement cannot include its derived tables

**Sections:** Program 2 §3–4; architecture §20.10.

```cddl
r = [* (uint // tstr // bstr)]
```

Scale this shape to p positions. The required `follow[p * ceil(p/32)]`
table alone has quadratic size in p, while there are O(p) nodes. Reading,
recomputing and comparing every [D] word cannot be O(nodes). Recursive
first/last/nullable sets also need a specified fixed-point/SCC procedure,
not an unqualified one-pass tree formula.

**Fix:** state verification complexity in Program words/bitset operations,
specify the recursive fixed point and saturating lengths, and retain a
charged verifier budget that covers these operations. This does not refute
the superset construction; it corrects the cost claim for verifying it.

### 14. Major — the proposed oracle can validate the policy while missing the bugs above

**Sections:** architecture §20.4, §20.11, §20.13.

The prototype returns `unknown` for the RFC §3.7 tag-unwrapping example
`r=[~tagged]; tagged=#6.99(uint)` on `[1]`, while Ruby returns rc0. Its
`groupValue` accepts only array/map unwrap targets. The report's new probe
for `.cborseq` gets a Ruby parse error, not a refusal. Neither outcome is
evidence against RFC semantics.

More fundamentally, an interpreter of §20.2 has no F/S/T code, no relaxed
queries, no ring, no memo cells, no arena and no charge scheduler. Boolean
agreement with it cannot certify those mechanisms or tier-independent
witnesses. An oracle written from both the RFC and this design is independent
implementation evidence, not independent confirmation that every policy
choice is required by the RFC.

**Fix:** keep RFC expectations, snug-policy expectations, reference-tool
observations and execution/resource invariants separate. Add metamorphic
forced-tier/driver checks; arbitrary valid encodings; committed and failed
cuts with named diagnostic keys; nullable huge minima; sentinel rows;
recursive stack collisions; nested occurrences; and resource boundary tests.
Treat unknown, parse error and timeout separately. Ensure the new oracle
implements tag unwrap and inherited type semantics rather than blindly
copying the prototype's gaps.

### 15. Note — the superset lemma holds under explicit finite-lowering obligations

**Sections:** architecture §20.5; Program 2 §4–5.

Consider any ENTRY test at i in a terminating PEG execution. Ignore failed
speculation that was undone and consider the successful consumption along
the currently active path from the root to that test. Its first i ENTRY
matches spell exactly the input prefix. Relaxing choices admits the selected
alternative; removing finite counts admits its repetition count; allowing
early exits admits its continuations. Hence the relaxed first/follow graph
has a path for that prefix ending with candidate p at i. Induction on the
consumed prefix shows p is in C_i, including a failing test at i. A test at
EOF uses the EOF rule, not a verdict bit.

For CALL, compute nullable/first/last to a least fixed point. Include callee
first positions at every call, all callee-last-to-call-follow edges, and
bypass every nullable call. Erasing the real call stack then admits every
finite call/return path of the PEG. It admits impossible return combinations
too, which only adds candidates. Center recursion
`g=(0,? g,1)` illustrates why the overapproximation is essential.

Generics require distinct substituted typesets/positions for distinct
instantiations, with shared recursive nodes only within equivalent bindings.
For `g<T>=(T,? g<T>)`, substituting `uint` must not share an ENTRY type
with a `tstr` instantiation. Compilation must finish with a finite graph or
give a compile-resource refusal. Unwrapped array/map choices are lowered
before this proof; tag unwrap produces a type ENTRY. `.cborseq` has a separate
virtual-array root, first set, records and EOF; its bytes are not outer
array elements. These are obligations of lowering, not exceptions to the
graph proof.

**Proposed disposition:** retain the lemma and require the fixed-point and
lowering rules explicitly. I found no counterexample to the lemma itself.
Do not present a proof for unresolved syntax as proof of its lowering.

### 16. Note — FL/B is a safe conservative bound, not an exact storage classification

**Sections:** architecture §20.5; Program 2 §3, §5.2.

For arrays, a failed ENTRY has consumed zero; a failing SEQ consists of
successful preceding children plus its failing child; a failing CHOICE has
only failed alternatives, each restarted at its initial index. A positive-
minimum REP can fail only before completing lo iterations, so at most lo−1
successful bodies precede the failing body. A zero-minimum REP cannot fail.
These facts justify the displayed FL upper bounds, with checked extended
arithmetic. A REP's backtrack point must use **FL(body)** for each failed
attempt, including the last failed attempt; using FL(REP(0,...)) would miss
all of them. Every non-last choice alternative contributes its own FL.
Failure of a last alternative propagates to its enclosing backtrack point,
whose FL covers that prefix.

Consequently, if the latest produced record has index i, any later needed
record j satisfies i−j≤B. B+1 ring records suffice. At EOF no new data row
should overwrite the ring. In `[? (int,int),int]` / `[1]`, B=1 is necessary
to replay the first element after the second is missing. The root being
unable to fail does not remove its children's failed-attempt rewinds.

Nor does B necessarily measure the records an optimized evaluator actually
needs. For example:

```cddl
r = [(* uint, tstr) // ()]
```

The failed first alternative can consume an unbounded uint prefix, giving
B=infinity. But its only fallback is EMPTY, which never reads an old record.
An evaluator can implement this shape with constant record memory even though
its index rewinds arbitrarily far. More generally, independent maxlen/FL sums
ignore type correlations and reachability, so FL itself need not be tight.
Conservative overclassification is safe.

CALL→infinity is also deliberately conservative: `g=(uint,?g)` has no
positive-length failed attempt that must be replayed, yet it becomes A2.
It is not evidence that all recursion intrinsically needs full records.

**Proposed disposition:** retain B as an upper bound; give pseudocode for
enumerating backtrack attempts and checked arithmetic. Do not call it an
exact/minimal ring requirement or turn safe overclassification into a wrong
Boolean result. Keep the ring access check as defense in depth, and treat
a violated compiler/verifier invariant as an internal/Program fault.

### 17. Note — F/S verdict equivalence is repairable; the missing conditions matter

**Sections:** architecture §20.5, §20.10; Program 2 §6.

For a flat sequence without finite-max nonliteral members, every nonliteral
member has unlimited room. A literal member can consume at most one pair
because valid maps have unique keys. Inducting over source members proves
that each pair goes to the first eligible matching member, and minimums are
checked in source order. A cut failure makes that sequence fail in both
modes; continuing a bookkeeping pass after recording it cannot rescue the
root. Thus F's Boolean proof works, subject to finding 6's normalization
restriction. The proof does not establish witness or charge equivalence.

For S, unnamed pairs cannot be consumed by any literal subtree. Root,
unbounded nonliteral members assign them in a source order unaffected by
slot choices. Their assignments can commute with literal-subtree processing,
provided the machine imports their counts/cut events exactly as in finding
12. Named slots must remain unassigned until the actual group runs.

In `r={* tstr=>any, ?(a:int,b:int)}` / `{a:"x"}`, the first member consumes
slot a before the optional subtree, so the result is accept in both modes.
In `r={* tstr=>any, (a:int // b:int)}` / `{a:1}`, it consumes a and the
required subtree fails. Giving literal slots priority would incorrectly
accept the second case. Keep both cases as S-versus-T regression tests.

**Proposed disposition:** retain the tiers after the stated repairs and gate
source-order slot consumption, counts, cut scope, witnesses and budgets.

## RFC ambiguity audit: every R1–R18

Quotations here are from the local RFC 8610 text. They support the precise
claim alongside them; they do not turn an implementation policy into an RFC
requirement. RFC 9682 replaces the collected grammar and changes escapes,
empty source files and #6/#7 head-number syntax; it does not settle these PEG
matching questions. In particular, §3.1 moves the at-least-one-rule requirement
to a semantic constraint after directive processing.

| Resolution | Assessment, authoritative text, example and disposition |
| --- | --- |
| **R1** | **Agree.** Appendix A: “locking in the first successful match and disregarding any further potential matches within the choice”. `[(int)//(int,int)]` rejects `[1,2]`. §2.1's “exactly match the elements of the array in order” supplies the final completeness check, not permission to re-enter a successful choice. |
| **R2** | **Agree.** Appendix A: occurrences “consume as much input as they match”; explicitly, '"*a a" in CDDL syntax never can match anything'. `[*uint,uint]` rejects `[1]`; `[?uint,2*3 uint,tstr]` rejects `[1,2,"x"]`. |
| **R3** | **Agree on verdicts.** Appendix A says numeric minimum/maximum notation “is copied”; Appendix C describes “the group repeated each of the occurrences times”. Greedy repeated-body evaluation followed by the minimum check is consistent. `[2*3 uint,uint]` rejects three uints and accepts four. Descending-count expansion is a semantic explanation, not an implementation that should repeatedly rescan the input. |
| **R4** | **Agree as an explicit terminating extension.** §3.2 requires a permitted number of concatenated body matches; Appendix C says “a (possibly infinite) group choice”. If the deterministic body succeeds empty, repeating it any finite required number succeeds empty identically. `[2*2 (?int)]` therefore accepts `[]` and `[1]`. The RFC does not prescribe the shortcut or its charges. Resolve finding 7; do not adopt Ruby's hang or failed minimum as authority. |
| **R5** | **Agree, with the normative tension acknowledged.** §2.2.2 says “union of the sets”; Appendix C explicitly adds “again using PEG semantics”, and Appendix A supplies lock-in. `{(?a:int)//(b:int)}` rejects `{b:1}`. §3.11's “optionality is attached to the first choice” supports the parse, and Appendix A then supplies the surprising empty lock-in. The union wording does not literally become true merely because non-overlapping cases agree. |
| **R6** | **Agree.** §3.5.4 expressly says the cut-free bad optional value “does match this specification” because “the second one (the wildcard) does”. `{?"optional-key"=>int,*tstr=>any}` accepts the RFC's bad-string example. No-cut means matching K **and** V for selection. |
| **R7** | **Agree for occurrence-governed members.** Appendix A's greed applies, and §3.5.3 says “the group expression tends to consume all matches”. `{*int=>int}` consumes all matching pairs; a default 1..1 member still takes just one. The quoted “tends” alone would not be a universal rule. |
| **R8** | **Agree as snug policy, not mandated RFC order.** §3.5.3 says “what is actually picked is indeterminate, but does matter”. `{int=>int,int=>6}` / `{3:5,4:6}` can thus depend on the implementation's pick. EC ordering determinizes it by value; reversing values gives rejection. §2.2.3 says CDDL “does not provide any language means to restrict the choice of serialization variants”, supporting serialization independence. Label this policy explicitly and fix finding 5 for diagnostics. |
| **R9** | **Reference mode is a deliberate deviation; rfc mode needs a complete scope definition.** §3.5.4: “so when it does not, the entire map fails to match”. Appendix A mentions disabling “alternatives in choices containing this choice”. `{(a:int)//(*tstr=>any)}` / `{a:"x"}` therefore cannot be called literal-RFC-conformant when accepted. Successful-cut propagation and iteration lifetime need finding 9's clarification. |
| **R10** | **Agree.** §3.5.4 says “later entries in the group of the map”, not earlier entries; §3.5.3 has selection from the remaining map after prior picks. `{*tstr=>any,?a:int}` accepts `{a:"x"}`. A required `"a"=>int` after that wildcard cannot obtain a. |
| **R11** | **Agree.** Appendix C's `memberkey = type1 S ["^" S] "=>"` imposes no singleton-key restriction. `{*tstr ^=>uint,*any=>any}` rejects `{a:"x"}` in either mode. Singleton byte/float handling must follow the actual key representation, not inherit a text/integer-only optimization accidentally. |
| **R12** | **Agree.** §3.2 requires concatenation of sequences “that the basic group entry matches”. A failed partial `(a:int,b:int)` is not such a sequence. `{*(a:int,b:int)}` rejects `{a:1}`; its failed attempt must restore consumption. With a following wildcard the reference mode can accept; rfc commitment is a separate question. |
| **R13** | **Agree.** Appendix C requires a sequence to match “the sequence of group entries in the sequence given”; it adds no distinct-schema-key constraint. `{?"a"=>int,?"a"=>tstr}` accepts `{a:"x"}` after the first member skips it. §3.2 separately notes that CBOR itself does not allow duplicate **data** keys. Do not confuse the two kinds of duplication. |
| **R14** | **Agree.** §3.9: “there is no way to satisfy the rule (i.e., the choice is empty)”. `$$x` is FAIL, not EMPTY. `{a:int,$$x}` rejects `{a:1}`; `{a:int,*$$x}` accepts it. |
| **R15** | **Agree with the operational policy; disagree that the conflicting text has been eliminated.** Appendix C literally says map pairs “can be ordered in such a way that the resulting sequence matches the group expression”. §3.5.3 explicitly discusses either a successful or unsuccessful pick for its pathological example. The latter is strong specific support for implementation-dependent picking rather than mandatory exhaustive permutation search. Record the tension and selected interpretation; do not claim Appendix C by itself specifies EC order or forbids search. |
| **R16** | **Agree on guarded group recursion; qualify refusal scope.** Appendix C says names may be used “in the rule itself and/or other rules”. `[g]`, `g=(0,?g,1)` accepts `[0,0,1,1]`. RFC 8610 does not itself state the draft's left-recursion rejection algorithm. That is a PEG termination/support policy, and a conservative check may also refuse unreachable recursive branches. Recursive generic expansion is additionally subject to compile-resource limits. Fix the stack before withdrawing the old refusal. |
| **R17** | **Partly agree; incomplete as written.** §3.7 unwrap exposes “the underlying group (for maps and arrays) or type (for tags)”. Include tag unwrap; the prototype does not. Appendix C enumeration matches “any value that is within the set of values that the values of the group given can take”, supporting ignoring occurrence for `&`. §3.8.4: “When the data items are taken as an array, the array matches the type” supports the virtual-array PEG. Distribution of unwrap over a choice of container types is a plausible explicit lowering rule, not a sentence supplied by §3.7. |
| **R18** | **Agree for a genuine type entry.** Appendix C: without memberkey, “the entry can only be used for matching arrays, not for maps”. `{uint}` is refused as map_key. Resolve named groups and unwrap first: `{g}`, `g=(a:int)` has a keyed group entry and must remain valid. |

## Explicit answers to the sixteen architecture questions

1. **Q1 — Reference cuts: agree as the selected compatibility semantics.**
   The completed probes reproduce the direct/parenthesized distinction and
   ordinary failure recovery. Do not describe it as full RFC behavior or
   infer all general PEG cases from D021's old DNF engine. Rule A is a
   different policy and should not quietly replace reference mode.
2. **Q2 — RFC cuts: disagree that the formalization is complete.** Global
   failure on bad cut values follows the literal text; commitment on successful
   keys is defensible. Repetition lifetime is inconsistent across prose,
   pseudocode, prototype and frame-bit wording (finding 9). Define it before
   offering the option as the RFC mode. A surrounding type choice may recover.
3. **Q3 — Pick order: agree with EC rather than wire order.** For the same
   map value, serialization should not change the pick. Unmarked maps really
   do have ascending EC=DC keys; marked maps already sort EC for duplicates.
   Retaining the permutation is economical. Its ownership/lifetime must span
   the PEG end-run, and cut diagnostics need finding 5's extra rule.
4. **Q4 — Empty iterations: agree with immediate satisfaction.** Repeating
   the same empty success until min supplies no new semantic information.
   Charge the shortcut explicitly; do not charge billions of redundant
   iterations or contradict it with count-to-FAIL saturation (finding 7).
5. **Q5 — Lock-in: agree.** No quoted text authorizes retry on final array
   completeness/map closedness. Preserve both the optional-empty lock-in and
   ordered-prefix examples in the corpus. Explain the §2.2.2 tension honestly.
6. **Q6 — Superset lemma: agree conditionally, with proof in finding 15.**
   CALL needs nullable bypasses and recursive fixed points; generic bindings
   need correct distinct typesets; unwrap/EMBED need explicit lowering. The
   finite-tree experiment found no break. Extra candidates cannot remove a
   Boolean match, though their work can cause resource refusals.
7. **Q7 — B: agree as a safe upper bound; disagree with “exactly”.** Use
   failed REP bodies and non-last alternatives as attempts, include nested
   attempts, and do not overwrite data at EOF. A1 needs B+1 rows. Calls and
   type correlations can overclassify safely; findings 1/8 concern additional
   storage, not a counterexample to the finite-tree read-back bound.
8. **Q8 — Memoization: disagree that the draft establishes the promised
   general complexity.** Maps have the quadratic counterexample. Reserve
   n_memo=0 for the initial format unless the array link machine, EOF cells
   and its amortized proof are delivered before implementation. If memoization
   is deferred, explicitly withdraw linear-time advertising and retain the
   budget contract. “No A2 in the corpus” does not justify leaving A2 untested.
9. **Q9 — Tier equivalence: agree for verdicts under the repaired conditions.**
   Findings 6/12/17 state the necessary restrictions and S state import. A
   root wildcard preceding a literal subtree must take named slots first.
   Disagree with the current witness equivalence claim (finding 5).
10. **Q10 — Witnesses: disagree that they are fully specified/tier-independent.**
    Array farthest-event ordering is deterministic for a fixed run; map
    consumption scores and cut witnesses require findings 5/12. Shallow
    end-of-map witnesses are an acceptable documented tradeoff. They need no
    payload keys and should remain a deliberate D024 amendment.
11. **Q11 — group_limit: agree with a distinct resource refusal.** Resource
    bounds may refuse otherwise valid data, as depth/items already do. With
    `r=[(*uint,tstr)//(*uint)]`, a tiny pegWords limit can fail after a handful
    of records while the work budget remains ample. Forcing budget to fail
    first by inflating record prices confuses memory and CPU accounting and
    still needs proof for recursive frames. Check capacity before writing;
    keep the refusal unskippable and document its precedence/offset.
12. **Q12 — Prices: disagree with adopting them as calibrated now.** D241
    measured the previous engines, not link compression, record copying,
    recursion saves or T scans. One “PEG step” covers differing work and
    consumed-record skips are not explicitly priced. No performance timing
    is claimed in this review. Measure the implemented generated JS/Rust
    paths on the reference environment and record results in bench/README
    before adoption; use operation charging meanwhile as a bounded-work
    contract, not an equal-CPU claim.
13. **Q13 — Format 2.0: agree.** Reusing S5–S10 with changed meanings and
    removing the old engine warrants a major bump under D084. Rejecting old
    containers is clearer than silently changing their semantics. A 1.2 with
    new leaf kinds is technically possible but retains both engines and
    compatibility cost. Different semantics after recompiling text is not
    itself an argument that immutable old Programs are invalid; the format
    change and deliberate support policy are the actual reasons.
14. **Q14 — Fail-fast pairs: agree as a sufficient Boolean doom test.** Every
    successful closed-map run assigns every pair to some MEMBER with both
    K and V true. If no member has both bits, no rollback, cut mode or tier
    can assign that pair. It is not a necessary doom test: some typed matches
    are unavailable because of maximums or group structure. Continue profile
    validation after schema death, and freeze M1's witness precedence.
15. **Q15 — Relaxed queries: agree with retaining the uniform policy initially.**
    Pure EXT predicates and nested validators may do extra deterministic
    work, as the current union evaluator already does. Their resource
    refusals must remain resource outcomes, not proof that the PEG rejects.
    Pruning A0 is optional future optimization that changes calls/charges;
    it needs a normative dispatch/charging rule or an explicit versioned
    schedule, not driver-dependent opportunism.
16. **Q16 — Literal-priority warning: agree.** Warn for a proved unreachable
    required member, e.g. `{*tstr=>any,"a"=>int}`. Preserve source-order PEG
    meaning. The analogous optional `{*tstr=>any,?a:int}` is a useful warning
    about an ineffective constraint. Warnings must not become schema refusals
    or require expensive general semantic containment analysis.

## Explicit answers to the four format questions

17. **Format Q1 — Memo columns: agree with reserving them initially.** Enforce
    n_memo=0 unless the complete memo/link semantics and sentinel layout are
    specified and tested before freeze. A later minor version may populate
    reserved fields only with an explicit loader capability/version rule;
    an old 2.0 loader must not accept unsupported memo programs accidentally.
18. **Format Q2 — Concatenated records: agree.** Fixed stride avoids an
    unbounded index per block and simplifies deterministic allocation. Define
    R_t from the blocks present at container entry and keep dead blocks'
    padding; recomputing stride as blocks die breaks old-record addressing.
    Charge actual initialized/copied words and account for aggregate arena
    pressure. A future compact layout is an optimization requiring equivalent
    public limits or an explicit changed resource contract.
19. **Format Q3 — Reason code: agree with new code 44 group_limit.** It
    distinguishes memory capacity from work exhaustion, fits the reserved
    range and permits callers to adjust the correct limit. Define which
    refusal wins when the same transition would exceed both limits. The
    parent arena exhausting inside EMBED must remain an unskippable resource
    outcome, rather than being swallowed as a recoverable schema alternative.
20. **Format Q4 — T literal lookup: agree with key-id→record index table.**
    Named keys are statically bounded and unique in valid input, making the
    n_named-word table useful for repeated literal tests. Initialize absent
    entries to −1, include initialization in charges/scratch, and use an
    actual named-key lookup under unsorted wire order (finding 3). Literal
    record lookup must still consult consumed state and the undo trail.

## Verdict

**Request changes before implementation freeze.** Proceed with D270's array
PEG direction, EC pick policy and a bounded group arena. Do not freeze the
current format/layout or claim general O(|G|*n), cross-driver charging identity,
or tier-independent witnesses. Resolve findings 1–4 first; then make cuts,
normalization, EOF memoization, diagnostics and allocation a complete
operational contract. The relaxed-query lemma and conservative finite-tree
ring bound survived this review under the explicit lowering assumptions above.

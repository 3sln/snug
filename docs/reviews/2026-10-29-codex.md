# Independent design review — 2026-10-29

Reviewed `docs/architecture.md`, `SPEC.md`, `DEVLOG.md`, and the referenced
3sln.me CDDL study and CBOR profile. Data below uses CBOR diagnostic notation;
hex examples are wire bytes. These are design counterexamples, not results
from an implemented snug validator. Seven refusal/counting assertions were
run against the copied reference codec, `bench/baseline/cbor-3sln.mjs`.
No network access was used.

1. **[blocker] Map group occurrence is not entry-wise multiplication (§4.3.3).**

   `r = { 1*2 (2*2 tstr => uint) }` permits exactly two or four pairs.
   Multiplying occurrences produces `2*4 tstr => uint`, accepting the invalid
   `{"a": 0, "b": 0, "c": 0}`. With several entries, repetition also couples
   their counts: in COSE mode, `{ 1*2 (tstr => uint, uint => uint) }` requires
   equal counts of text and integer keys; independently multiplying both
   ranges accepts two text keys and one integer key. Both examples avoid the
   overlapping-key problem addressed by §4.3.2.
   **Fix:** preserve the repetition's shared iteration count and attainable
   count vectors, expand bounded repetitions exactly, or refuse them. Do not
   lower a repeated group to independent entry intervals.

2. **[major] Literal-key groups can repeat when individual copies are nullable (§4.3.3).**

   `r = { 2*2 (? a: uint, ? b: uint) }` accepts `{}`: each of the two group
   copies can be empty. It also accepts `{"a": 1, "b": 2}`, assigning one
   member to each copy. Thus “minimum above one is unsatisfiable” is false.
   Required literal members prohibit repeating those members, not repeating
   an arbitrary group containing literals.
   **Fix:** reason about group nullability and choices before clamping; retain
   exact occurrence semantics or explicitly document a conservative refusal.

3. **[blocker] Literal ownership does not make factors independent (§4.3.4).**

   `r = { ? "a" => uint, * tstr => tstr }` accepts `{"a": "x"}` through
   non-cut fall-through. Routing `"a"` exclusively to its literal factor
   rejects it. A stronger case is
   `r = { ? ("a" => uint, "b" => uint), * tstr => any }` with `{"a": 1}`:
   the whole optional group must be absent and the residual must consume
   `"a"`. No independent literal-factor decision can consume that pair while
   satisfying the group. The determinism rule permits both schemas because
   their residual is absorbing.
   **Fix:** prove independence over complete key domains and assignments,
   including the residual. Otherwise retain joint alternatives. An absorbing
   residual might support a specialized proof and per-alternative forwarding,
   but “pairs no factor owns” is insufficient.

4. **[major] Explicit cuts on key typesets have no specified implementation (§4.3.2).**

   `r = { * tstr ^ => uint, * tstr => any }` must reject `{"a": "x"}`:
   the first entry's matching key commits its value constraint. The stated
   cut rule handles only literal-key entries, so ordinary greedy assignment
   falls through and accepts. This schema passes the absorbing-entry rule.
   Literal-first reordering also needs justification in the presence of
   explicit cuts, rather than inheriting the cut-free matching proof.
   **Fix:** specify cut scope, priority, occurrence availability, and failure
   transitions for every permitted member-key form; initially refuse explicit
   key-typeset cuts if necessary. Keep the implied cut for `:`.

5. **[note] The restricted, flat, cut-free greedy argument does hold (§4.3.2).**

   Under the stated rule, any entry with a positive minimum or finite maximum
   has a key domain disjoint from every other constrained entry. Its eligible
   pairs therefore cannot be stolen by another constrained entry, and later
   absorbing entries can take leftovers. I found no counterexample to this
   restricted claim. Two overlapping required entries are refused, so they
   cannot be used as an accepted-schema counterexample. For example,
   `{ tstr => 0, tstr => 1 }` is refused even though distinct value domains
   make `{"a": 0, "b": 1}` unambiguous.
   **Fix:** state the restricted lemma and its assumptions, then separately
   prove normalization, factoring, and cuts preserve them. Optionally prove
   disjointness of complete key/value predicates to accept more schemas.

6. **[blocker] Following-position disjointness does not imply one live count (§4.4).**

   `r = [? uint, 2*3 uint, tstr]` passes the proposed test: the counted
   entry's following entry is `tstr`, disjoint from `uint`. After two uints,
   however, that same position has live counts **1 and 2**, depending on
   whether the optional prefix consumed the first uint. Both histories matter:
   arrays with two uints followed by text and four uints followed by text are
   valid. Keeping only the smaller or larger count loses one of those cases.
   This already fails without nested groups or group choices.
   **Fix:** prove unique count over all incoming automaton histories, not just
   disjointness at the repetition's exit. Otherwise unroll or carry bounded
   sets of `(position, count)` configurations. Specify nested group repetition
   before claiming exact array semantics.

7. **[major] Typesets need Boolean obligations and local embedded failures (§§4.1–4.2, 4.6).**

   A union of operand leaves is only an evaluation worklist, not a substitute
   for an AND result. For `r = ([uint] .and [tstr]) / [bool]`, `[1]` matches
   an internal operand but no root alternative. Likewise,
   `r = bstr / (bstr .cbor uint)` must accept `h'ff'`: embedded CBOR failure
   kills only the controlled branch, not the ordinary byte-string branch.
   Unconditionally propagating the fused scanner's embedded profile error
   would reject a valid value. Tags also need to associate each content result
   with its requesting tag leaf.
   **Fix:** define queried leaves separately from internal dependencies,
   compute each AND from both operand results, and scope `.cbor`/`.cborseq`
   parsing and errors to their requesting predicates. Include exact embedded
   span boundaries and full-consumption checks. Guarded recursion can use
   this model, but it needs finite graph identities and separate per-depth
   state; “subset construction” alone does not establish these invariants.

8. **[major] Literal-control lowering can discard the target constraint (§4.6).**

   `(tstr .size 1) .eq "aa"` is empty, whereas a replacement `LIT "aa"`
   accepts `"aa"`. `(tstr .size 1) .ne "x"` must reject both `"aa"` and
   integer `0`; a bare `NOTLIT "x"` does neither. Also, `(0..10) .ne 5`
   cannot be represented by one interval.
   **Fix:** lower these to target intersection with equality/inequality unless
   implication has been proved. Split numeric exclusions into ranges or use
   an AND predicate. Make this explicit rather than relying on an unspecified
   “control combinations” fallback.

9. **[major] Work is not bounded by data items times leaf width (§§4.1, 7).**

   A megabyte of text is one item but requires a megabyte of UTF-8 work.
   One MAP leaf can contain many alternatives and entries while all their
   values share one leaf. One ARRAY leaf can contain thousands of positions;
   its follow graph can have quadratically many edges. Hashing/comparing long
   keys, union construction, AND dependencies, tag-content inspection, and
   repeated embedded interpretations add work outside the stated formula.
   Fixed schema limits can make validation linear in input bytes, but the
   coefficient is substantially larger than typeset width.
   **Fix:** give a bound in bytes, active predicates, map entry tests, automaton
   edges/bitset operations, and embedded interpretation depth. A conservative
   width check is feasible by capping all reachable leaf identities, including
   dependency closure; it does not bound those other dimensions. Account for
   them separately without enumerating all possible subsets.

10. **[major] The step budget omits attacker-controlled loops (§7).**

    `r = tstr` charges only one leaf evaluation regardless of string length.
    `r = #6.86(bstr)` can scan a large payload for NaNs at nearly the same
    charge as an empty typed array. An open-addressing key lookup can probe
    many colliding schema literals, and a pair/alternative assignment can
    inspect many entries while costing one unit. Follow-set unions and set
    sorting/merging have similar hidden loops. A four-million-step ceiling
    consequently does not bound these operations as claimed.
    **Fix:** charge before bounded byte blocks, probes, entry tests, dependency
    edges, and bitset operations; define their traversal order. Include all
    profile-only work and use checked/saturating arithmetic. Measure the worst
    permitted primitive mix, not an average step cost.

11. **[major] The regexp transition complexity is asserted, not designed (§4.7).**

    Bitsets alone do not give `O(length × ceil(positions/32))` for a general
    Glushkov automaton. Computing the next set by OR-ing every active
    position's follow mask costs up to `O(positions²/32)` per code point.
    Independent regexps multiply this work further.
    **Fix:** specify the transition algorithm and its tables, prove its time
    and space bounds, and charge its actual operations. A bounded Thompson
    simulation is a simpler alternative if the stronger bit-parallel bound
    cannot be justified.

12. **[major] Compilation itself lacks a work and allocation budget (§§5.1, 7).**

    Many independent choices can generate an exponential Cartesian product
    before the final alternative/Program limit is checked. Expanding generics
    such as `g<T> = [g<[T, T]>]` can also do substantial intermediate work
    before reaching the instantiation limit. Constant folding can grow the
    byte pool, which has no explicit size limit. A parser depth bound is
    mentioned but absent from the limit table.
    **Fix:** budget compilation steps, temporary bytes, pool bytes, nesting,
    and total scratch bytes. Check every expansion/allocation prospectively,
    use graph sharing, and check multiplication before reserving arenas.
    Give the `bus` boundedness analysis explicit treatment of recursion and
    all branches. Final-output limits cannot replace intermediate limits.

13. **[major] Fixed memory is possible, but the sizing formula and limits are insufficient (§8).**

    An array item may simultaneously match many ARRAY leaves; allocating
    `depth × max positions` is insufficient when that means the per-type
    position maximum. All live arrays' states are needed. The analogous map
    product, including factors, can dominate memory despite small leaf width.
    Even 16 Mi Program words already occupy 64 MiB before the byte pool and
    depth-multiplied scratch. There is no total allocation ceiling or defined
    refusal for a schema whose scratch would exceed the host's capacity.
    **Fix:** compute aggregate simultaneous state, cap Program-plus-pool-plus-
    scratch bytes, and refuse before allocation. Define per-call limit
    overrides so they cannot exceed the allocated depth/state capacity.
    For Rust, make scratch per validation context or require exclusive schema
    access; the JS single-thread argument does not establish Rust concurrency
    semantics. The wasm fallback must also account for its input copy.

14. **[major] Failure location does not uniquely determine a reason or path (§6).**

    With `r = (uint .lt 3) / 9` and input `5`, both leaves fail at the same
    scalar, with different natural reasons (`range`, `value`). “First point”
    does not choose between them. `{ a: uint, b: uint }` against `{}` leaves
    two missing members even after selecting an alternative. AND dependencies,
    factor failure, and embedded failure add further ties. No algorithm defines
    “survived longest” or compile order after hash-consing and normalization.
    **Fix:** define ordered failure witnesses, tie-breaking, missing-member
    selection, and propagation through Boolean/container predicates. Specify
    whether a literal key must be named in the current map context. Render
    paths exclusively from verified schema key ids; make `#tag` a fixed marker
    or schema-derived tag, never an arbitrary received tag number. I found no
    direct key-payload leak if that restriction is maintained.

15. **[major] Generic tag traversal disagrees with reference item counting (§§4.5, 7).**

    The reference accepts `d8 45 40` (tag 69, empty byte string) with
    `{top: 'any', maxItems: 1}`. Its specialized tag parser does not count the
    byte-string content as another item. A generic TAG-content child visit
    that increments the ordinary item counter refuses it. The same distinction
    affects bignums; decimal/ndarray structural arrays have different counting
    behavior. “Typed array = 1” is insufficient to specify the whole walk.
    **Fix:** separate schema predicate visits from profile data-item counting.
    Publish exact counting/depth rules for each allowed tag and test limit
    boundaries against the reference.

16. **[major] Fused profile checking needs exact refusal precedence and a complete code list (§§4.5, 6).**

    Confirmed reference results with `top: 'any'`: `c4 98 02 20 0f` returns
    `decimal`, not `non_shortest` (the decimal parser first demands byte
    `82`); `c4 82 00 18 00` returns `non_shortest`, before complaining about
    the invalid exponent; `fa 40000000` returns `float`, before shortest-width
    failure. Reserved head `1c` returns `malformed`; default-top decode of
    `00` returns `not_map`. The latter two codes, and the profile's disallowed-
    tag code, are missing from §6's CBOR list. In COSE mode the reference also
    refuses unsafe integer labels: `a1 1b 0020000000000000 00` is `key_type`,
    despite §3's broad “allows integer labels” wording.
    **Fix:** specify the scanner's ordered checks, top/COSE options, label
    range, and complete code mapping before fusion. Explicitly cover the
    profile's tag-nesting restriction and declared-length checks before
    container processing. Add multiply-invalid vectors; single-fault vectors
    do not establish precedence. Distinguish profile checks from schema
    failures when deciding which may stop early.

17. **[major] Validated bytes are not necessarily stable for an unchecked builder (§§8–9, D017).**

    A JS `Uint8Array` can have `SharedArrayBuffer` backing. Another worker can
    change its lengths, types, or values after validation and before/during
    building. The supposedly trusted second pass can then construct values
    that were never validated. User-supplied wrapper constructors can likewise
    mutate retained input if called before building finishes.
    **Fix:** reject shared backing or take a private snapshot, require stable
    input throughout both passes, and defer user callbacks until parsing is
    complete. Include the copy cost in D017 measurements where copying is
    required. Ordinary synchronous decoding of private bytes can retain the
    two-pass design.

18. **[major] A structural Program verifier does not establish the promised safety (§5.2).**

    A cache can keep every offset/id in range while changing its declared
    scratch size to one word, changing limits, or creating inconsistent
    derived widths/masks. Offset validation alone does not prevent arena
    overrun. A structurally valid change to a literal or transition can also
    silently change the schema's meaning.
    **Fix:** recompute or validate all derived sizes and semantic invariants,
    bound verifier work, and use checked accesses where invariants remain
    untrusted. Bind cached content to the expected schema/options with an
    integrity mechanism appropriate to the cache's trust boundary, or
    recompile. An embedded schema hash alone does not verify Program contents.

19. **[major] The host/kin refusal boundary contradicts the encoder design (§2, §9, D003–D004).**

    D003 says no host contains a refusal, but a hand-written encoder must
    refuse unsupported host classes, NaN, malformed wrappers, cycles, sparse
    arrays, invalid strings, and out-of-limit values. Checking only emitted
    bytes cannot detect every invalid source value or prevent work performed
    before bytes exist. JS and Rust also expose different value models.
    **Fix:** explicitly assign host-value admissibility to hosts and require
    shared vectors, while retaining CBOR/schema decisions in kin; alternatively
    define a kin-driven encoder decision protocol. State cross-host identity
    for corresponding abstract values and for byte/schema validation, rather
    than promising identical behavior for unrelated host objects.

20. **[minor] Several advertised semantics still lack implementable definitions (§§4.6, 5.1; study §3).**

    The lowering table only gives `uint .size n`, although the study explicitly
    requires `uint .size (0..7)` to constrain byte capacity rather than the
    integer value to 0..7. RFC 9165 controls are called supported while their
    implementation is deferred to an unnamed later phase. Project controls
    for equal-length columns, uniqueness, and code-point length remain open;
    those are existing contract requirements, not merely optional features.
    **Fix:** enumerate the accepted control operand forms and release scope.
    Add discriminating vectors for uint size zero/ranges, bstr bit positions
    across byte boundaries, the complete prelude, and encoded float widths.
    The documented `uint`/`integer`/`number` and float-width distinctions are
    appropriate; preserve them. Gate migration on project-control decisions
    or an explicit remaining application-validation layer.

21. **[minor] The scanner benchmark is too narrow to select the JS target (§10, D005).**

    A generated scanner can pass 1.25× while the full VM performs poorly on
    set unions, large follow tables, many alternatives, or compiler workloads.
    Conversely, JS can narrowly fail that ratio yet still beat wasm after
    copying and startup. Comparing scanner gzip sizes does not establish the
    size of compiler + validator + host + glue.
    **Fix:** use the scanner as an early gate, then repeat the decision on
    representative compiled schemas and hostile cases, with complete artifacts,
    startup, peak memory, and end-to-end JS/wasm latency. Define which workloads
    must satisfy the ratio and preserve a correctness gate before performance.

22. **[note] Keep D017 provisional and make the 40 KB target measurable (§§9, 12).**

    Two-pass decode preserves a useful allocation boundary; there is no design
    evidence yet that replacing it with callbacks is worthwhile. “Second pass
    costs more than ~25%” lacks a denominator and does not compare a real
    fused implementation. The 40 KB target simultaneously includes a full
    compiler, multiple automata engines, strict codec, wrappers, and a custom
    target's output, with no size allocation or fallback scope.
    **Fix:** measure complete check-plus-build latency against the baseline and
    a fused prototype, recording invalid-input allocation behavior. Report
    compiler, runtime, and host sizes separately as well as their combined
    import; support a precompiled-schema runtime artifact if browser size
    requires it. Treat the size target as an experiment until measured.

**Overall verdict:** revise before freezing the Program format or implementing
the general matcher. Type-set evaluation remains a plausible foundation, and
the flat cut-free map restriction has a useful proof, but the present group,
factor, and counter rules break exactness. The resource and refusal contracts
also need operational definitions before cross-host identity can be tested.

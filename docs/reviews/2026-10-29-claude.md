# Independent design review (Claude, reviewer A) — 2026-10-29

Reviewed architecture revision 1. Delivered as an agent report; recorded here
verbatim in substance by the manager (headings and findings preserved,
lightly condensed). Disposition of every finding: architecture §15 and DEVLOG P0.4.

1. BLOCKER §4.3.4 factors not exact. (a) `{ ? (a: int, b: int), * tstr => any }` with `{a:1}`: routing `a` only to its factor rejects; RFC accepts. (b) `{ ? (a: int, b: int), ((* tstr => int) // (* tstr => tstr)) }` with `{a:1, c:"x"}`: independent factor states accept; RFC rejects. (c) top-level `//` spanning literal and typeset entries correlates factors. Fix: top-level map `//` → separate MAP leaves; factorise only sequences; keep factor F separate only if (1) its literal keys are disjoint from every residual key typeset, or (2) the residual has one alternative and every residual entry overlapping F's keys is absorbing — then an F-alternative not consuming a pair survives iff the residual accepts the pair (count-independent predicate). Otherwise merge.
2. BLOCKER §4.3.3 group occurrence wrong both ways: `{ + (email: tstr // phone: tstr) }` with both keys valid but clamped away; `{ 2*2 (? a: int) }` satisfiable; `{ 0*2 (2*2 tstr => int) }` with `{x:1}` accepted by multiplication (true set {0,2,4}); coupled counts across entries. Fix: literal-only `n*m G` = unions of n..m alternatives of G with pairwise disjoint key sets; typeset groups multiplied only when every inner entry is absorbing or the count is fixed; else refuse. Add a brute-force existential matcher oracle.
3. BLOCKER §4.4 counter condition checks the wrong side: `[* (int, int), 3*3 uint]` with `[1,2,3]`/`[1,2,3,4,5]` valid gives count sets {1,3}. Fix: a counter only if no predecessor q≠p of p can match the same values as p (p is then never re-entered while active).
4. MAJOR §6/§4.6 local failures treated as global: `bstr .cbor {a: int} / bstr .size (0..16)` with `h'ff'`; embedded limits charged to the message; `#6.2(bstr .size 9) / integer`. Fix: failure only when emptiness reaches the root, report the deepest emptying point on that chain; `.cbor` is a sub-validation with its own depth/items accounting and reason `embedded`; path segment for embedded content.
5. MAJOR §4.5/§6 profile vs schema order undefined; cbor.mjs check order must be copied exactly (too_large; not_map by peeking byte 0, empty input → not_map; items counted before head; depth then truncated (n / 2n remaining) then too_many_entries; key_type by peeking; tag 4 demands 0x82 then decodes the array then checks; tag 40 likewise; bignum/typed content peeked; float before non_shortest; f8 xx<24 non_shortest else simple; AI 28–30 malformed; stray 0xff indefinite; counting rules). Fix: profile errors always win (continue profile-only after a schema failure); an order-of-checks table; differential mutation fuzzing on codes.
6. MAJOR §4.3.2 cut semantics: RFC says the entire map fails; snug kills one alternative (sensible, must be documented); literal-before-typeset priority changes `{ * tstr => any, ? "a": int }` with `{a:"x"}`; typeset cuts and cut-at-max unspecified. Fix: refuse a cut literal entry following an overlapping key-typeset entry in source order; specify typeset cuts; document the alternative-local reading.
7. MAJOR §7 budget does not bound time: Glushkov follow unions, map entry scans, literal compares, .bits/.size scans, hash-table probe clustering by untrusted schemas, regexp Follow(D) cost. Fix: charge actual work; sorted key table + binary search; specify regexp simulation (chunk tables, lower max ~512); charge |S| per item; compile budget.
8. MAJOR width/memory: width bound via the depth-chain closure R_k; large enums need a LITSET leaf; scratch words limit; per-call limits may only lower compiled ones; one lazily grown scratch per isolate rather than per schema (1000 manifests × 1 MB); Rust &mut or pool; 100 open-map message types keep many alternatives live — index alternatives by literal key, publish a per-item cost bound.
9. MAJOR kin/JS practicality: kin.lang emits plain a[i], +, * — Rust panics/overflow, JS undefined|0; decide checked access and wrapping forms in P1.1 and fuzz JS vs Rust from P1. Exact decimal→binary64 parsing of CDDL float literals is unplanned. 40 KB unrealistic (estimate 40–60 KB gzip): split runtime (≤20 KB) from a lazily loaded compiler; first-class Program serialisation keyed by SHA-256 of text+options+version; VM must bounds-check scratch or the cache be authenticated. D005 measures only the scanner — add a compiler slice, a zero-disagreement fuzz gate, workerd cold start; the wasm fallback is less bad than stated since validation allocates nothing.
10. MINOR error model: total order for "survived longest"; render a literal key only if a live alternative names it (else the path reveals the payload contains that key); typeset-matched key → value or unexpected?; encoder refusals contradict D003.
11. MINOR duplicate literal keys within an alternative arise from `$$ext //=` composition; drop unsatisfiable alternatives rather than refuse.
12. MINOR gaps: `#6.<type>`, `#7.25/26/27`, bare `#6`/`#7`, undefined `$$socket`; productivity check wrongly refuses regular group recursion in arrays; `.feature` could be a no-op; `uint .size (lo..hi)`; whether ranges cover bignums; cycle-aware hash-consing.
13. MINOR project controls: uniqueness feasible within R3 with scratch from the entries limit, O(n log n); others constant memory.
14. NOTE D017: measure text-heavy bodies; builder must get the same options the VM ran with.

Verdict: core design right (set-based, no backtracking, greedy proof holds for flat alternatives, type-set evaluation exact), not ready to build until factors, group occurrence, counters, failure semantics and the cost model are fixed in the document.

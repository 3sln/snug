# Distribution channels and kin targets (P9.19, 2026-11-12)

This is an assessment for the coordinator and the owner. It builds nothing
and publishes nothing. The `dist` branch design is in
[release-policy §9](../release-policy.md); the decision is in D346, unticked.

**Babashka pod / Clojure: dropped by the owner 2026-11-12.** There is no
Clojure or babashka distribution, so neither Clojars nor deps.edn is
assessed here.

## 1. Channels: what the current docs say

Network access was available. Every page below was fetched on 2026-11-12.

**Recommendation:**
- npmjs for both npm packages.
- crates.io for the crate.
- GitHub Releases for the raw `.wasm` modules, the tarballs, the `.crate`,
  `SHA256SUMS` and a source archive.
- The `dist` branch for git-source consumers.
- GitHub Packages for nothing. Its npm registry makes every consumer of a
  public library create a token, and it cannot hold the crate.

Release-policy §9 has the table.

## 2. Local validation of the `dist` branch

Validation ran on 2026-11-12 on macOS arm64 with Node 24.6.0, npm 11.5.1,
cargo 1.92.0 and Go 1.21.3. It ran offline, against a stamped build of the
P9.15 rework tree (`p915r` at 5698c68, `bb stamp 0.1.0`, then `npm pack`
and `cargo package`). The script was `node kin/scripts/dist-test.mjs`.

**Passed:**
- two builds gave the same commit, `486c390d42d9`, and the same tag object;
- the rebuild was refused;
- the npm install from `git+file://…#v0.1.0` held 119 files, equal to the
  tarball's, and validated a schema;
- `#semver:0.1.0` resolved to the dist commit;
- the cargo `git` + `tag` dependency built and validated;
- a probe Go module resolved as `github.com/3sln/snug/go v0.1.0` through
  `go/v0.1.0`. Git's `url.insteadOf` mapped the GitHub URL to the scratch
  repository, with `GOPROXY=direct` and `GOSUMDB=off`.

A second release was also tried by hand:
- `0.1.1` was chained onto the branch as a child commit;
- the diff from 0.1.0 is 8 files, 10 lines: the version in the shipped
  trees (package.json, version.mjs, the generated compiler in JS and Rust,
  Cargo.toml, Cargo.toml.orig, Cargo.lock) and `DIST.json`;
- a cargo dependency on `tag = "v0.1.0"` still pins the first commit.

**Found on the way:**
1. Tagging the source `vX.Y.Z` and the dist commit `dist/vX.Y.Z` makes
   npm's `#semver:` resolve to the source commit, and the install fails.
   This is why release-policy §9 puts `v…` on the dist commit.
2. npm cannot resolve any ref when the remote's HEAD branch does not exist.
3. Before Clojure was dropped, a deps.edn consumer (`:git/tag` + 7-character
   `:git/sha` + `:deps/root`) and a `bb.edn` consumer also resolved. That
   is recorded only as evidence that the layout would take one.

## 3. kin targets today

| Target | Emitter | Generated output | Gates | Parity |
| --- | --- | --- | --- | --- |
| JS | snug's own `kin.lang` arms, `kin/src/snug/js.cljc` (332 lines). kin has no JS target, D005/D018. | `gen/js`: 50 files, 42,968 lines | every identity gate, npm-test, size, node-oldest, rfc-corpus, proptest | the reference arm of every identity gate |
| Rust | kin's `kt/rust` with snug's operator templates (`snug/lang.cljc`) | `gen/rust`: 50 files, 40,197 lines | every identity gate, rust-api-test (+ full), msrv, crate-diff, regexp-diff | JS == Rust on check, scan, rscan, vm, vmsession, sequence, compile (identity), compile-fuzz, nav, write, unicode, abnf |
| wasm | not a kin target: the Rust output built for wasm32 (`host/wasm`, 1,361 lines) | two modules (SDK, compiler) | wasm-sdk-test, wasm-size | SDK == native JS on vm-test's case set |

- **kin's own targets** (`kin/target.cljc` `defaults`): Rust, Go, Java and
  C#. Go's form vocabulary is complete in `kin/lang.cljc`.
- **Use elsewhere:** emon and nome generate Go, Java and C# at scale. emon
  has 352k lines of generated Go and hand-written Go hosts of about 9.3k
  lines; nome's are about 4.8k lines.
- **Missing:** kin has no Clojure, Python, C, Zig or Swift emitter. Any of
  those would be a kin change, outside snug's control.

**The generated core is 32-bit only.**
- It has no u64, i64, float or bigint (D009). Wide integers, floats and
  float16 live in the host layer.
- That maps cleanly to Go (`int32`, `uint32` casts for `ushr` and `ult`).
- Go wraps on overflow silently, so the debug-overflow net stays
  Rust-only.

## 4. Go: what it would take

| Work | Engineer-days |
| --- | --- |
| `:go` arms in `snug/lang.cljc` (8 tags, about 40 operator templates), a `:go` entry in `targets.cljc` (vfs `gen/go`, `kl/flat-array` data), the first full emit of 50 sources (29k lines of kin), and fixing Go-only refusals (unused locals and imports, reserved names, `int(i)` index casts) | 2–4 |
| `bb check` / `bb drift` with a Go arm (hello probe, `go vet`) | 0.5 |
| Go host: Value with u64 and `math/big` bignums, decode and encode, float16/32/64, Schema, Program and serialisation, View and Cursor, blob, stream and sequence sessions over `io.Reader`, the compile API, Unicode tables, errors. The Rust host is 5.8k lines. | 8–12 |
| Parity: about 10 stdin/stdout drivers (Rust's are 1.55k lines), and a third arm in each identity gate's script and `.mjs` comparison | 3–5 |
| `go-api-test` (public API vs JS, as rust-api-test does), `docs/go.md`, examples | 3–4 |
| Packaging: assemble `go/` (gen and host in one module) in the release build, pass it to `dist.mjs --overlay`, a `go-oldest` gate, the release set | 1–2 |
| **Total** | **18–28** |

- **kin needs no new emitter.** The risk is that snug's surface finds Go
  emitter bugs that emon and nome never hit. Any such bug stops the work
  under "Found in kin" (AGENTS.md).
- **Ongoing costs:**
  - every identity gate gets a third arm, so gate runs get longer;
  - every behaviour change needs three hosts.
- **Distribution needs no extra design.** Go would use the `dist` tree:
  - main holds the placeholder version that kin writes into every Program;
  - a Go module cannot import files from outside its directory.

  So `go/` is assembled at release, and `dist.mjs` tags `go/vX.Y.Z`.
- **Java and C#** also have kin emitters, at a similar cost or higher.
  - The JVM needs signed `byte` masking.
  - The JVM has 64 KB method and constant limits for the data tables.
  - Nobody has asked for them (D006).

## 5. Recommendation

- **Before the RC:**
  - no new target;
  - land `dist.mjs` with the release tooling, since it costs nothing to the
    gates.
- **After the RC:**
  - Go, only when a consumer asks (D006's reason still holds), at 18–28
    engineer-days;
  - nothing else.
